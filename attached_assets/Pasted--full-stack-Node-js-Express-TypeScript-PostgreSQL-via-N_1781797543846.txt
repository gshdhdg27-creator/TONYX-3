Ты — опытный full-stack разработчик (Node.js, Express, TypeScript, PostgreSQL via Neon, React). Твоя задача — провести полный аудит кодовой базы проекта TONYX-3 и исправить накопившиеся технические долги, баги и несоответствия типов.

Сфокусируйся на следующих критически важных зонах:

1. БАЗА ДАННЫХ И ТИПЫ (Drizzle ORM & Neon PostgreSQL):
   - Убедись, что колонка `bonusPct` (и любые другие процентные/финансовые поля) имеет тип numeric(5,2) для точных вычислений. Код не должен приводить их к integer.
   - Проверь все файлы миграций и файлы схем в папке `02_db`. Убедись, что типы, генерируемые Drizzle, полностью соответствуют реальной схеме в базе данных.

2. ВАЛИДАЦИЯ И API (Zod & Express):
   - Проверь папки `03_api_zod`, `04_api_spec_client` и `05_api_server`. 
   - Схемы Zod должны строго валидировать входящие данные для механики частичного выкупа (partial buyout). На бэкенде должна быть жесткая проверка минимальных лимитов на покупку (минимальный шаг и остаток токенов).
   - Убедись, что при частичном выкупе ордера балансы пользователей (TON/TONYX) обновляются атомарно (в рамках одной транзакции базы данных), чтобы исключить race conditions (состояние гонки).

3. СИНХРОНИЗАЦИЯ ТИПОВ (TypeScript):
   - Устрани любые несоответствия типов (Type mismatches) между серверными ответами (Express) и клиентскими запросами. Если схема бэкенда изменилась, обнови клиентские спецификации API.
   - Проверь фронтенд-компоненты (особенно модалку `BuyOrderModal` и логику автокоррекции ввода пользователя), чтобы они ожидали правильные типы данных от API (например, string для numeric-полей из базы, если они парсятся как строки, или корректно приводи их к number).

4. ЛОКАЛИЗАЦИЯ И i18n:
   - Проверь файлы локализации (i18n). Убедись, что для всех новых элементов маркетплейса, карточек ордеров и системных уведомлений добавлены корректные переводы как на русский, так и на английский языки. Не должно быть пустых ключей или хардкода.
