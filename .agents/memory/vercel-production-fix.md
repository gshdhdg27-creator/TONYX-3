## Root Cause of Production HTTP 500s
`db/src/index.ts` used a top-level `await import(...)` pattern. Without `NEON_DATABASE_URL` set in Vercel, it silently fell back to an in-memory PGlite instance — all writes were lost on every request, all reads returned empty. Now throws an explicit error with instructions instead.

**Why:** Vercel serverless functions are stateless; PGlite in-memory state is destroyed after each invocation.

## Required Vercel Environment Variables
Both must be set in Vercel Dashboard → Settings → Environment Variables, then Redeploy:
- `NEON_DATABASE_URL` — Neon PostgreSQL connection string
- `TELEGRAM_BOT_TOKEN` — Telegram bot token

## Diagnostic Endpoint
`GET /api-debug` — returns env var presence status without exposing values. Use after deploy to verify.

## Bugs Fixed (June 2026 full audit)
1. **Silent PGlite fallback** (`db/src/index.ts`) — now throws in production with clear instructions.
2. **CORS missing header** (`api-server/src/app.ts`) — `x-telegram-init-data` added to allowedHeaders.
3. **History mines status** (`routes/mini/history.ts`) — checked `"cashout"` but mines sets `"won"` on cashout; all wins showed as losses.
4. **Duplicate admin route** (`routes/mini/admin.ts`) — `GET /online-count` defined twice; second copy was dead code, removed.
5. **Leaderboard label** (`mini-app/src/pages/leaderboard.tsx`) — `valueLabel` said `"coins"` for top_earn; corrected to `"TONYX"`.

## Architecture Notes
- Vercel entry: `api/server.ts` imports `api/_bundled.mjs` (generated by `node scripts/bundle-api.mjs`).
- `NODE_ENV` is hardcoded to `"production"` in esbuild define (`api-server/build-vercel.mjs`).
- All mini-app API calls use relative paths `/api/...` — no hardcoded base URL.
- OWNER_ID `"7257793582"` hardcoded in both `admin.ts` and `admin.tsx` — single source of truth, do not change without updating both.
