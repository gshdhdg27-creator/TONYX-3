Теперь реализуем самую главную и важную логику — автоматическую коррекцию поля ввода (input) при частичном выкупе ордера, чтобы защитить рынок от поломки лимитов и появления «неликвидных хвостов».

МЕХАНИКА ИСПРАВЛЕНИЯ СУММЫ НА ЛЕТУ (Фронтенд и Бэкенд):
Когда пользователь открывает модальное окно чужого ордера и хочет выкупить его ЧАСТЬ, он вводит сумму в TON. Система должна жестко контролировать остаток на ордере. Нам ЗАПРЕЩЕНО оставлять на ордере сумму меньше минималки этого тира.

Пусть:
- Total — полная текущая стоимость ордера на рынке в TON.
- Min — минимальная сумма выкупа/остатка для данного тира (1 для START, 10 для BASE, 25 для PRO, 50 для ELITE).
- X — значение, которое юзер вводит в поле ввода (input).

ПРАВИЛО ОГРАНИЧЕНИЯ И АВТО-КОРРЕКЦИИ:
1. Значение X физически не может быть меньше Min (если вводит меньше, принудительно ставить Min).
2. Максимальное значение для ЧАСТИЧНОГО выкупа рассчитывается как: Max_Partial = Total - Min.
3. Если пользователь пытается ввести число X, которое БОЛЬШЕ чем Max_Partial, но МЕНЬШЕ чем Total (например, ордер 50 TON, тир PRO с Min=25, а юзер вводит 40 TON), интерфейс должен МОМЕНТАЛЬНО автоматически стереть его ввод и подставить значение Max_Partial (в данном примере принудительно выставить 25 TON). Пользователь физически не должен иметь возможности отправить форму с запрещенным остатком.
4. Если пользователь нажимает кнопку "MAX", поле ввода должно автоматически заполниться значением Total (то есть выкуп ордера целиком в 0, что разрешено).

ПРИМЕР ДЛЯ ТИРА PRO (Total = 50 TON, Min = 25 TON):
- Юзер пишет 25 -> Разрешить (остаток 25).
- Юзер пишет 40 -> Инпут автоматически сбрасывает на 25 и не дает поднять выше, так как остаток 10 TON запрещен.
- Юзер жмет MAX -> Инпут ставит 50 (полный выкуп).
