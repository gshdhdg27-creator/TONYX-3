# TONYX Pixel Office Swarm — 0.5

Офис: http://127.0.0.1:8799. Запуск двойным нажатием **Открыть офис.cmd**. Нужен Node.js 22+; для проверки сайтов используется Playwright. Офис доступен на ноутбуке и через закрытую ссылку Tailscale (см. ниже). Закрытие вкладки не останавливает работу; для текущей задачи есть кнопка остановки.

## Команда

| Департамент | Лидер | Два помощника |
|---|---|---|
| Архитектура и контекст | Атлас | Стратег, Логос |
| Разработка и код | Код | Спринтер, Флинт |
| UI/UX и анимации | Пикси | Моти, Адапт |
| Безопасность и QA | Скаут | Тестер, Сейф |

12 ролей не означают 12 разных моделей: некоторые роли используют одну модель в независимых запросах. В настройках сохранены запрошенные идентификаторы и показаны фактические модели. Недоступные бесплатные варианты заменены доступными кандидатами; качество замен не гарантируется. Выбранная пользователем модель не заменяется молча.

## Подключение

- OpenRouter: вставьте ключ в «Подключениях». Каталог фильтруется по нулевой цене входа/выхода, суффиксу `:free` и поддержке инструментов. Платного резервного маршрута нет.
- Groq: отдельное поле ключа и подтверждение Free-тарифа. Офис не может проверить тариф через API, поэтому нельзя использовать ключ платного Developer-аккаунта. После подключения доступные Qwen/Llama появятся в каталоге; автоматическая конфигурация может выбрать их для соответствующих ролей.
- SiliconFlow не активирован: постоянная нулевая цена запрошенных моделей не подтверждена. Пробные кредиты не считаются постоянным бесплатным доступом.
- В локальном режиме ключи хранятся только в памяти сервера и очищаются при перезапуске. Они не выводятся в журнал и не включаются в экспорт.

После обновления нужно повторно ввести ключ. Регистрация и создание ключей выполняются пользователем через ссылки в настройках. Не передавайте ключи в чате.

## Конвейер

1. Планирование: Стратег и Логос дают выводы, Атлас формирует frontend/backend-план, критерии приёмки и проверки. Атлас может получить до двух PNG/JPEG/WebP-макетов по 2 МБ. Модель без поддержки изображений отклоняет такую задачу.
2. Первичный код: Спринтер готовит набросок.
3. Доработка: Код и Флинт дорабатывают общий набор файлов. При необходимости подключается весь UI-департамент. Тестер готовит тесты для фактического стека.
4. Аудит: Сейф проверяет типы, initData и границы доверия; Скаут — безопасность и логику. Ошибки возвращаются Коду, до двух циклов исправлений. Отрицательное ревью или ошибка синтаксиса блокирует готовый результат.

Участники работают последовательно и видят подготовленные изменения коллег. Статусы персонажей отражают реальные запросы и обращения к файлам.

## Проверки и ограничения

Автоматически выполняются разбор JSON, синтаксическая проверка JavaScript и Python AST (если Python установлен). Генерируемый Python не исполняется. PyTest/Jest, TypeScript-сборка, браузерные тесты, БД и Web3-транзакции автоматически не запускаются. Сгенерированные тесты и положительное AI-ревью не доказывают работоспособность приложения.

Задания и прочитанные исходники отправляются выбранным поставщикам. `.env`, каталоги учётных данных, ключи, бинарные файлы и пути через символические ссылки заблокированы. Произвольные секреты внутри обычного кода автоматически распознать нельзя.

Найденная копия TONYX-3 использует Node/TypeScript. Описание Python/aiogram — целевой контекст, а не разрешение на миграцию: агенты учитывают фактические файлы.

Фото- и видеогенераторы не подключены. Поддерживаются код, SVG, CSS/Canvas/WebGL-анимации, текстовые OBJ/glTF и сценарии Blender. Codex, ChatGPT и прямой Gemini остаются отдельными, неподключёнными сервисами.

## Файлы и GitHub

Изменения сначала сохраняются в задаче отдельно от исходной папки. «Применить к проекту» проверяет отсутствие конфликтов, сохраняет оригиналы в `data/backups/<id>/changes.json` и записывает результат локально.

Для автоматической отправки в GitHub подключите Fine-grained token только для `gshdhdg27-creator/TONYX-3`, разрешение **Contents: Read and write**. После успешного аудита создаётся ветка `pixel-office/<дата>-<id>`. Основная ветка не меняется. Если GitHub-файл отличается от исходника задачи, отправка останавливается. Без ключа результат ожидает подключения; аккаунт GitHub в Codex не подключает эту программу автоматически.

История и подготовленные файлы хранятся в `data/`. Старые настройки сохранены в `data/settings.before-swarm.json`. Незавершённые задачи после перезапуска помечаются прерванными.

Проверки разработки: `node --test tests/*.test.mjs`. Тесты используют имитацию поставщиков, не тратят облачную квоту и не публикуют ничего в настоящий GitHub.

## Версия 0.5: чат, телефон, GitHub и Vercel

Вверху страницы доступен чат со всей командой или сотрудником. Личный диалог по умолчанию не изменяет файлы.

Закрытая ссылка для телефона: https://<имя-ноутбука>.<tailnet>.ts.net/ . Tailscale должен быть включён на телефоне под аккаунтом владельца ноутбука. Ноутбук и офис должны работать. Отдельный gateway слушает только 127.0.0.1:18800, проверяет личность владельца из Tailscale Serve и Origin; публичный Funnel не используется. Запуск «Открыть офис.cmd» также запускает gateway.

В «Подключениях» нужны отдельные ключи GitHub и Vercel. Подключения этого чата недоступны самостоятельному серверу. Ключи остаются в памяти до перезапуска. Vercel проверяет привязку к выбранному GitHub-репозиторию; настройки по умолчанию взяты из локального .vercel/project.json.

После положительного ревью код автоматически отправляется в ветку pixel-office/... . Основная ветка не меняется. Для публикации основной версии нужно слияние. Vercel Git Integration должна собирать ветки; офис не создаёт платные ресурсы и не переключает тариф.

Офис отслеживает только деплой своего точного commit SHA, до 15 минут, и показывает ошибки. При ошибке сборки или подтверждённой ошибке сайта Код готовит исправление, Сейф и Скаут проверяют его, затем исправление отправляется в ту же ветку без force-push. Максимум две попытки; они расходуют бесплатную квоту моделей. Внешние изменения ветки останавливают автоматическую отправку.

После READY проверяется HTTP-ответ и открывается страница в чистом Chromium с мобильным размером экрана. Сохраняются снимок и ошибки JavaScript. Запись на сайт, WebSocket, сторонние домены и service workers заблокированы в проверочном браузере. Защищённый Preview, перенаправление или ограниченная загрузка отмечаются явно. Проверка не заменяет тесты Telegram, TON, платежей, входа и всех пользовательских действий. Скриншот доступен в результате задачи. Исходные тесты проекта по-прежнему не запускаются автоматически.

Для браузерной проверки теперь нужны зависимости: npm ci и npx playwright install chromium (уже установлены на этом ноутбуке). Статусы и журналы сохраняются без ключей; известные секреты маскируются, но не добавляйте секретные данные в логи приложения.



## Облачная версия 0.6 — телефон без ноутбука

Развёртывается отдельный сервис `tonyx-pixel-office`, не старый backend TONYX-3.
Ссылка запуска: https://render.com/deploy?repo=https://github.com/gshdhdg27-creator/TONYX-3/tree/pixel-office-cloud

В Render выберите бесплатный тариф Free и заполните закрытые поля:
- GITHUB_TOKEN: доступ к TONYX-3, Contents Read and write.
- OPENROUTER_API_KEY: ключ OpenRouter. Используются только модели с нулевой ценой и поддержкой инструментов.
- VERCEL_TOKEN: ключ аккаунта с доступом к связанному проекту Vercel.

Render автоматически создаст OFFICE_PASSWORD. Сохраните его в менеджере паролей. Вход в офис: имя `office`, этот пароль. Откройте выданную Render HTTPS-ссылку с телефона; Tailscale и включённый ноутбук больше не нужны.
Ключи в облаке сохраняются в закрытых переменных Render. Введённые в интерфейсе замены действуют только до перезапуска: для постоянной замены обновите Environment в Render.

История, настройки и подготовленные файлы сохраняются с AES-256-GCM в отдельной ветке `pixel-office-state`; ключ шифрования получается из OFFICE_PASSWORD. Не меняйте этот пароль без экспорта/переноса истории — старая копия перестанет расшифровываться. Два экземпляра не должны писать в одну ветку. Снимки проверочного браузера не архивируются. При внезапной остановке возможна потеря последних 30 секунд; прерванные задания отмечаются, а не выдаются за выполненные.

Render Free засыпает после простоя; открытие может занять около минуты. Это не гарантированный круглосуточный фоновый исполнитель. Поддерживайте страницу открытой во время длинной задачи. Офис использует актуальную main при первом запуске контейнера; после слияния новых изменений выполните новый деплой сервиса, чтобы получить новую копию. Если обнаружен конфликт исходников, отправка блокируется.

Ошибки 429/502/503/504 переключают модель максимум на две доступные бесплатные замены, с записью в журнал. Исчерпанная дневная квота аккаунта останавливает задачу. Поиск по проекту и пакетное чтение сокращают лишние запросы. Платные резервные модели не включаются.

Локальные автоматические тесты используют имитации провайдеров, GitHub и Vercel; они не доказывают доступность внешних моделей или успешность облачного деплоя. Docker-образ требует отдельной проверки сборкой в Render.
